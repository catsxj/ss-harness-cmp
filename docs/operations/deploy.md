# 生产构建与部署验证

> dev 模式验证通过 ≠ 生产环境可用
> 每个子应用迁移完后，必须在类生产环境中验证

---

## 生产构建验证清单

### 构建产物检查

```
[ ] vue-cli-service build 成功（无报错）
[ ] 产物目录结构正确（outputDir 与部署路径一致）
[ ] 静态资源路径正确（publicPath 配置）
[ ] 无未解析的环境变量（检查产物中是否有 process.env.VUE_APP_XXX 残留）
[ ] 包体积合理（对比迁移前的 bundle size）
```

### 部署环境验证

```
[ ] Nginx / 网关配置的静态资源路由是否匹配新的产物结构
[ ] 子应用的 entry URL 在生产环境中可访问
[ ] Qiankun 基座能通过生产 URL 加载迁移后的子应用
[ ] CORS 头正确（子应用跨域加载）
[ ] 生产环境的 API 代理/网关配置无需修改（接口路径未变）
```

### 功能验证（生产/预发布环境）

```
[ ] 登录 → 进入迁移后的子应用 → 核心功能正常
[ ] 与 csc-web（Vue 2，独立部署）切换正常
[ ] 图表/可视化组件在生产环境中渲染正常
[ ] 静态图片/字体等资源全部加载（无 404）
[ ] 异步路由加载正常（chunk 文件可访问）
```

## 部署顺序建议

```
1. 先部署到测试/预发布环境
2. 跑新旧共存联调测试（见 coexistence-testing.md）
3. 灰度发布（如有条件）：部分用户使用新版本
4. 全量发布
5. 保留旧版本 7 天（回滚窗口）
6. 确认无问题后清理旧版本
```
